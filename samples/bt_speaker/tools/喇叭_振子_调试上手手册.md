## 1. 硬件拓扑

三颗外置音频功放，全部**软件 I2C（GPIO bitbang）+ 使能脚（PND/PDN 高=使能）**驱动，共用同一路 **I2STX0**（BCLK=GPIO39、LRCLK=GPIO6、DIN=GPIO38）。

| 设备 | 芯片 | 负载 | 软件 I2C | 7位/8位地址 | 使能脚 |
|---|---|---|---|---|---|
| ACM2（chip0） | ACM8636 | 喇叭左 | SCL=GPIO0/SDA=GPIO1（`I2C_0`） | 0x1D / 0x3A | PND=GPIO5 |
| ACM1（chip1） | ACM8636 | 喇叭右 | SCL=GPIO34/SDA=GPIO33（`GPIO_2`） | 0x1C / 0x38 | PND=GPIO35 |
| U4 | ACM8625S | 振子 | SCL=GPIO11/SDA=GPIO16（`I2C_3`） | 0x2C / 0x58 | PDN=GPIO40 |

- **ADR 电阻决定地址**：两颗 ACM8636 的 ADR 选择电阻不同，ACM2=0x1D、ACM1=0x1C（用户确认的硬件信息，勿再改回 0x1C 给 chip0）。
- ACM8636 与 ACM8635 同一套寄存器表、芯片 ID 相同（FC=0x86/FD=0x25/FE=0x53）。
- 三颗芯片各走独立软件 I2C；`I2C_0` 仅连 ACM2，**不与面板 CN2 共享**。

## 3. 代码现状（当前生效的设计）

### 3.1 `drivers/codec_acm8636/driver.c` — AMP 驱动（关键）

- 注册：`DEVICE_AND_API_INIT(acm8636, CONFIG_AMP_DEV_NAME, acm8636_init, ...)`，**init 优先级 45**（POST_KERNEL）。`audio_out_init` 是 50，会主动调 `amp_open`，所以加了 **惰性 I2C 绑定** `acm8636_ensure_i2c_bound()`（防 `amp_open` 先于驱动 init 用 NULL i2c_dev）。
- `amp_open`（开机，audio_out_init 调用）：PND 高 → 写 init 表(8条) → 延时 → 写 main 表(660条) → 音量 → 清 fault。**开机时 BCLK 未运行，此表时钟参数无效**（这是后续无声的伏笔）。
- `amp_start`（每次播放，DMA 起流后 30ms 触发）当前逻辑：
  1. `acm8636_pdn_set_all(true)`（幂等，**不 toggle**——toggle 会复位芯片）
  2. probe chip0（读 r15/ctrl/stat；失败 → GPIO 总线恢复 + `full_init` 兜底）
  3. **若 `!data->main_loaded_with_bclk`：重写整个 main 表（BCLK 在跑 → 芯片捕获正确时钟/PLL 参数）+ 音量，置标志**（首次播放一次性，约 200ms 软件 I2C，可接受）
  4. 音量 + `play_enable`（page0 `0x04=0x03`）
  5. **不要**写 fault-clear（`0x01=0x80`）——在 BCLK 运行时写会打断时钟锁定导致静音（fault 是只读状态，不影响播放）
- `amp_stop`：只清标志（PND 保持高，寄存器保留）。
- `amp_close`：PND 全拉低，重置 `inited` 和 `main_loaded_with_bclk`。
- 诊断打印：`amp_open` 里 pre/post-init 芯片 ID + init fault；`amp_start` 里 probe + `first play` 日志。
- `struct acm8636_device_data`：`{volume, inited, main_loaded_with_bclk}`。

### 3.3 参考 SDK 的关键差异（为什么它稳定）

`C:\msys64\home\s1916\ZS285L2\drivers\codec_acm8635\driver.c`（ACM8635）：
- **大表 658 条只在设备 init 写一次**（`acm8635_load_reg_tables`）。
- `amp_start` 正常路径**只写音量(12B)+播放使能(1B)** ≈17 次 I2C，不重写大表。
- `amp_open` 不写寄存器仅日志。
- 只有掉线（probe 失败）才走 "last resort" 重载大表。
- 播放链路：`audio_out_init → amp_open`；播放 → `acm8635_schedule_amp_start`（DMA start 后 30ms）→ `amp_start`。
- 参考 SDK 的 AVRCP Target features 也是 0x0002（不含 Cat4，同样不支持手机音量同步——我们的 0x000A 是增强）。

**我们与参考的差异**：ACM8636 在无 BCLK 时写表时钟不锁，必须首次播放（BCLK 在跑）重写一次；参考的 ACM8635 无此问题（或未暴露）。

### 3.4 功能说明：音量同步 + 自动重连

**① 手机音量与音箱音量同步（AVRCP 绝对音量）**
- 配置：`CONFIG_BT_AVRCP=y` + `CONFIG_BT_AVRCP_VOL_SYNC=y` + `CONFIG_VOLUME_MANAGER=y`（prj.conf）。
- 前提：AVRCP Target 的 SDP Supported Features 必须含 **Category 4（绝对音量）**——`register_sdp.c` 已从 `0x0002` 改为 `0x000A`（Cat2+Cat4，§4.7）。
- 行为：手机勾选「同步设备音量」后，调节手机音量 → 音箱音量跟随（`set_volume_cb → bt_manager_avrcp_sync_vol_to_local` → 系统音量 → 功放 `set_volume` 0-16 档）。
- ⚠️ 手机需**重新连接/配对**（SDP 连接时查询能力）才能识别新 features。

**② 开机自动连接已连接过的手机（自动重连）**
- 机制：bt_manager 内建（`bt_manager.c` 的 `auto_reconnect_work` + `btif_br_auto_reconnect_*`），开机 BT 使能后自动重连**上次连接的 BR 设备**（`btif_br_set_autoconn_info_need_update(1)` 记录设备顺序，`BT_MAX_AUTOCONN_DEV`）。
- 相关配置：`CONFIG_BT_MAX_PAIRED=4` / `CONFIG_BT_MAX_BR_PAIRED=2`（配对记录容量）、`CONFIG_BT_SCAN_WITH_IDENTITY=y`（按身份连接已配对设备）。
- 行为：开机自动回连上次配对的手机；断开后也按策略尝试重连。

## 4. 调试历史（已完成修复，勿重复排查）

按时间顺序的问题 → 根因 → 修复。**新会话直接跳到 §6 遗留问题**。

### 4.1 固件崩溃（最早）
- 现象：崩溃日志首个 CPU Exception。
- 根因：`amp_open` 被 `audio_out_init`(50) 提前调用，此时 acm8636 驱动 init(66) 未跑，`i2c_dev` 为 NULL → 空指针。
- 修复：init 优先级 66→**45** + 惰性 I2C 绑定 `acm8636_ensure_i2c_bound()`。
- 经验：分析崩溃日志看**第一个** CPU Exception（后面的多是崩溃链次要故障）。

### 4.2 I2C 地址错误
- 根因：chip0 曾配 0x1C，实际 ACM2 是 0x1D（ADR 电阻不同）。
- 修复：`CHIP0_ADDR=0x1D`，Kconfig 默认同步。

### 4.3 Subwoofer 会话冲突
- 根因：`AOUT_I2STX_SESSION_MAX=1`，2.1ch 需要 2 个 session，subwoofer 轨道创建失败阻塞整个播放 → 无声音。
- 修复：改 2.0ch（`MULTI_CHANNEL_MODE=0`，SUBWOOFER off）。硬件也仅一根 SDIN，本来就该 2.0。

### 4.4 A2DP stream 为 NULL（无声音根因之一）
- 现象：`_bt_manager_a2dp_callback: stream is null`。
- 根因：缺 `BT_AUDIO_STREAM_CONFIG_CODEC` 事件处理，codec 协商未填充 `sink_chan.handle/id`。
- 修复：`samples/bt_speaker/src/btmusic/btmusic_event.c` 增加 `BT_AUDIO_STREAM_CONFIG_CODEC` case（从参考 SDK 移植）。修复后日志出现 `bt_manager_set_stream: stream: 0x00099500 type 0`（stream 有效）。

### 4.5 断续声音（acl full 重启循环）
- 现象：`<CT-W> acl full` 刷屏 → `playback:in:0` → `[faps]detect in rate abnormal` → `btmusic_player_reset_trigger: restart` → 循环。
- 根因：`amp_start` **每次播放都重写 660×2=1320 次软件 I2C（约 200ms CPU 忙等）** → 蓝牙 A2DP 数据无人消费 → 控制器 ACL 缓冲满 → 播放重启。
- 修复：改为**仅首次播放重写**（`main_loaded_with_bclk` 标志），后续走快速路径。

### 4.6 完全无声（CLK_FAULT）
- 现象：修复 4.5 后（不重写大表）完全没声音，播放时 chip0 `0x18=0x04`（CLK_FAULT）。
- 根因：**ACM8636 的时钟/PLL 参数在写寄存器表那一刻捕获**。开机 init 写大表时无 BCLK → 时钟参数无效；播放时 `play_enable`（写 0x04=0x03）触发状态切换 → 锁定失败 → CLK_FAULT → 静音。
  - 关键证据：probe 时 0x18=0x00（看似锁），`play_enable` 后 0x18=0x04。有声版（4.5 前）因每次重写大表（BCLK 在跑）时钟参数正确。
- 修复：**首次播放无条件重写大表**（BCLK 在跑 → 芯片捕获正确时钟参数）；**移除播放时的 fault-clear**（写 0x01=0x80 会打断时钟锁定）；`amp_open` 重置标志。

### 4.7 手机「同步设备音量」无法勾选
- 根因：本机 AVRCP Target 的 SDP Supported Features = 0x0002（仅 Category 2），缺 Category 4（Amplifier/绝对音量）。
- 修复：`ext/actions/bluetooth/bt_stack/src/bt_stack/register_sdp.c` 的 `avrcp_target_attrs` features `0x0002 → 0x000A`（Cat2+Cat4）。TG 音量处理链路本来就有（`set_volume_cb → bt_manager_avrcp_sync_vol_to_local`）。
- 注意：手机需**重新连接/配对**（SDP 连接时查询）才能识别。

## 5. 日志解读指南（分析新日志用）

| 日志 | 含义 / 动作 |
|---|---|
| `amp_open (PND high + full init)` | 开机初始化开始 |
| `chip N id (pre/post-init) fc=0x86 fd=0x25 fe=0x53` | 芯片 ID。**0x86/0x25/0x53 正常**；0x00 异常（当前问题之一） |
| `chip N init fault 0x17=0x.. 0x18=0x.. 0x19=0x..` | 开机 fault 快照；**0x18 bit2 = CLK_FAULT（无 BCLK，开机时正常）** |
| `amp_start probe chip0 r15=.. ctrl=0x03 stat=..` | 播放时 probe；ctrl=0x03 播放态 |
| `first play: reload main table with BCLK present` | 首次播放重写大表（预期只出现一次） |
| `amp_start done vol=8` | amp_start 完成 |
| `<CT-W> acl full` | 蓝牙控制器 ACL 缓冲满 → A2DP 消费慢/CPU 被长阻塞（应消失） |
| `playback:in:0 de:0 res:.. out:0` | 播放数据流停（正常播放时 in/de/out 持续 >0） |
| `[faps]detect in rate abnormal` | FAPS 速率异常 → 即将触发播放重启 |
| `btmusic_player_reset_trigger: restart` | 播放器重启（断续的直接原因） |
| `[msg_err] send msg XX ms larger than 50 ms` | 有 XX ms 长阻塞（曾定位大表重写 200ms） |
| `bt_manager_set_stream: stream: 0x.. type 0` | stream 有效（有声音的前提） |
| `_bt_manager_a2dp_callback: stream is null` | stream 为 NULL（无声音，检查 4.4） |
| `BT_AVRCP_EVENT_VOLUME_CHANGED` / 手机音量同步 | AVRCP 绝对音量（需 SDP Cat4，§4.7） |

## 9. 重要注意事项（避免踩坑）

- **PND 只能拉高不能 toggle**：`amp_start` 里 `pdn_set_all(true)` 是幂等；toggle 会复位芯片，丢失寄存器配置。
- **播放路径不要做长软件 I2C**：任何 >几十 ms 的阻塞都会触发 `acl full` → 播放重启（断续）。大表重写只在首次播放一次。
- **功放输出时序（关键）**：表尾保持静音（`0x04=0x00`），`play_enable` 只在首次重写（BCLK、静音下）捕获有效时钟后才解静音；不要在播放路径用 fault-clear（`0x01=0x80`）兜底——会打断时钟锁定。
- 编译配置以 `prj.conf` 为准，注意 `.config` 是否刷新。
- 参考 SDK（ZS285L2）是权威对照，遇到音频配置问题先对比它的 `prj.conf` 和 `codec_acm8635/driver.c`。
- 用户只让 AI 改代码/分析，不编译、不烧录（除非用户明确要求）。

## 10. 本次调试完整总结（2026-08-06，可作另一 SDK 参考）

### 10.1 「只有右声道」问题 = 4 层根因叠加（由浅入深，每修一层暴露下一层）

**层 1：寄存器大表缺 TDM/Sub mixer 配置 → 功放输入路由只剩右声道**
- 现象：ACM1（右）响、ACM2（左）不响。
- 根因：大表从旧 ACM8635 导出复制，缺厂商新导出（`ACM8635_export_new.c`）的 **TDM 段（page0 0x07=0x02、0x08/0x09/0x1b=0x00）** + **Sub mixer 尾段（page4 0x34~0x37=0x00）** 共 8 寄存器。
- 修复：补齐后脚本按（页,寄存器）diff，确认与厂商导出一致（其余 649 条 0 差异）。
- 经验：功放大表必须跟**厂商最新 GUI 导出**对齐（尤其输入路由/TDM 段）。

**层 2：A2DP codec 结构体未初始化 → 音频流被配成单声道**
- 现象：修完层 1 仍只有一边响。
- 根因：`bt_manager_a2dp.c` 的 `BTSRV_A2DP_CODEC_INFO` 里 `struct bt_audio_codec codec;` **未初始化**（栈垃圾）；A2DP 栈只传 2 字节（codec 类型+采样率），`locations` 等字段全是垃圾 → `stream_config_codec` 用垃圾 `locations` 算出 `channels 1/locations 4(FC)`（日志：sdu=43124/octets=60772 乱值）。
- 修复：`memset(&codec,0,sizeof(codec))` + `codec.locations = BT_AUDIO_LOCATIONS_FL|BT_AUDIO_LOCATIONS_FR`（=3 → channels 2）。
- 关键枚举（codec.h）：`FL=BIT(0)=1`、`FR=BIT(1)=2`、`FC=BIT(2)=4`。
- 经验：**栈上协议结构体必须 memset**；A2DP 声道由 `locations` 决定，与手机 SBC/AAC 帧声道无关。

**层 3：首次播放 660×2 条软件 I2C 重写阻塞 ~608ms → `acl full` → 播放重启**
- 现象：修完层 2 完全无声（首次播放被一次重启打死）。
- 根因：首次重写实测阻塞 ~608ms（文档早期估 200ms），BT 线程无法消费 A2DP → `acl full` ×46 → `playback:in:0` → FAPS 异常 → `btmusic_player_reset_trigger: restart`。
- 修复：写表函数加 `yield`，首次重写每 32 条 `k_sleep(1)`，让 BT 线程排空控制器缓冲。
- 经验：**播放路径严禁长 CPU 忙等**；必须阻塞的任务要周期性让出 CPU。

**层 4：芯片开机即 play 态、坏配置驱动输出级 → Class-D 误过流 → 静音**
- 现象：修完层 3 播放链路完全正常（数据流、时钟锁定 f18=0x00），但喇叭 1s 电流音后完全静音。
- 根因：芯片从开机就是 play 态（大表末尾 `0x04=0x03` 解静音），但启动配置是**无 BCLK 时捕获的坏时钟参数**；BCLK 一跑输出级就用坏配置驱动 → Class-D **误过流锁存**（`0x17` CH2_OC/CH1_OC，清后立即复现、在 CH1/CH2 间跳动=非固定短路）→ 静音。
- 修复：① 大表末尾改保持静音（`0x04=0x00`）② `amp_start` 的 `play_enable`（`0x04=0x03`）作为唯一解静音点——首次重写（BCLK、静音下）捕获有效时钟后才解。
- 经验：**功放配置/重写期间必须保持静音，拿到有效时钟后再解静音**；用 `printk` 打故障寄存器（0x17/0x18/0x19）定位静音最快。
