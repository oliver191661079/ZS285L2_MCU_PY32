# ATS2853P2 + ACM8635 音频调试记录

## 1. 硬件架构

### 1.1 芯片连接

```
ATS2853P2 (蓝牙 SoC)                  ACM8635 (DSP 功放)
┌─────────────────────┐              ┌──────────────────┐
│ I2STX0:              │              │                  │
│   GPIO6  (LRCLK) ───┼──────────────┤  I2S LRCLK        │
│   GPIO39 (BCLK)  ───┼──────────────┤  I2S BCLK         │
│   GPIO38 (DOUT)  ───┼──────────────┤  I2S SDIN         │
│                      │              │                  │
│ I2C (software GPIO): │              │                  │
│   GPIO0  (SCL)   ───┼──────────────┤  I2C SCL          │
│   GPIO19 (SDA)   ───┼──────────────┤  I2C SDA (addr 0x1C) │
│                      │              │                  │
│ GPIO5 (PDN)      ───┼──────────────┤  PDNz (低有效关机) │
│                      │              │                  │
│                  扬声器←────────────┤  SPK+ / SPK-     │
└─────────────────────┘              └──────────────────┘
```

### 1.2 关键配置

| 参数 | 值 | 说明 |
|------|-----|------|
| I2C 地址 | 0x1C (7-bit) / 0x38 (8-bit wire) | ADDR 引脚接地 |
| I2C 方式 | GPIO bitbang (GPIO0/19) | 软件模拟 I2C，100kHz |
| I2S 格式 | I2STX0, 48kHz, 32-bit, 立体声 | 标准 I2S |
| PDN 引脚 | GPIO5 | 低有效，运行需拉高 |
| 初始化音量 | 8/16 (约 -18.5dB / 0dB) | `CONFIG_CODEC_ACM8635_INIT_VOLUME` |
| DSP 固件 | adMUSIC.dsp | 音频 DSP 处理链路 |

### 1.3 配置文件

```kconfig
# prj.conf 关键项
CONFIG_CODEC_ACM8635=y
CONFIG_CODEC_ACM8635_I2C_BITBANG=y       # GPIO0/19 软件 I2C
CONFIG_CODEC_ACM8635_INIT_VOLUME=8       # 初始音量（0-16）
CONFIG_CODEC_ACM8635_I2C_ADDR=0x1C
CONFIG_CODEC_ACM8635_PDN_GPIO=5
CONFIG_I2C_GPIO_1=y
CONFIG_I2C_GPIO_1_SCL_PIN=0
CONFIG_I2C_GPIO_1_SDA_PIN=19
CONFIG_AUDIO_OUT_I2STX0_SUPPORT=y        # I2S TX0 输出
CONFIG_I2S_0=y
```

## 2. 音频通路

### 2.1 蓝牙 A2DP 播放流程

```
蓝牙 A2DP 数据
  → ringbuff_stream（环缓冲）
    → media_player（解码 + DSP 效果）
      → audio_track（I2S DMA 输出）
        → I2STX0（GPIO6/39/38）
          → ACM8635 I2S 输入
            → ACM8635 DSP（EQ/DRC/音量）
              → ClassD 功放 → 扬声器
```

### 2.2 音量控制

系统音量（0-16）通过 `amp_set_volume()` → ACM8635 寄存器 `volumeControl`（0x15 寄存器 bit 4:0）设置。

音量表（硬件 codec 级）：
- 16 → 0dB（最大）
- 8 → 约 -18.5dB
- 0 → 静音（约 -109.5dB）

系统初始化时 `CONFIG_CODEC_ACM8635_INIT_VOLUME=8`，手机蓝牙音量同步后可以调到最大 16。

### 2.3 寄存器加载流程

```
1. acm8635_reg_tab_init    → 基础初始寄存器
2. k_sleep(10ms)           → DSP 初始化等待
3. acm8635_reg_tab_main    → 主配置表（含 EQ/DRC）
4. amp_set_volume(8)       → 设置初始音量
5. acm8635_amp_start()     → 启动功放
```

## 3. 调试经历与教训

### 3.1 音频无声 —— 律动灯 irq_lock 干扰

**现象**：蓝牙 A2DP 无声音输出。

**排查过程**：
1. ACM8635 寄存器配置正确（I2C 通信正常，寄存器回读一致）
2. I2S 引脚配置正确（GPIO6/39/38 MFP=0x9）
3. 将 WS2812 律动灯刷新关闭（`BTMUSIC_RGB_RHYTHM_LED_SHOW=0`）后，音频恢复正常

**根因**：WS2812 bitbang 用了 `irq_lock()` 关闭所有 CPU 中断约 5ms（176 LED × 1.2µs × 24bit）。期间音频 DMA 完成中断无法响应，I2S DMA 缓冲区欠载 → 无声。

**教训**：GPIO bitbang 的 `irq_lock` 与音频 DMA 互斥。在同一个 MCU 上同时做 WS2812 和音频，必须用 DMA 驱动灯带（SPI+DMA 或定时器+DMA），或者把灯带交给外部 MCU。

### 3.2 音频噗噗声 —— 多种因素叠加

**现象**：蓝牙和本地播放都有间歇性噗噗声。

**排查过程**：
1. 尝试 DSP 能量采集 → 噗噗声。关闭后蓝牙恢复，但本地仍有噗声。
2. 尝试 `audio_policy_set_user_dynamic_waterlevel_ms(20/30/50)` → 反而加重噗声。
3. 尝试 SPI1+DMA 驱动 WS2812 → 理论上零 irq_lock，但 DMA 控制器与音频 DMA 竞争，仍有噗声。
4. **最终确认**：完全关闭 WS2812 刷新（`BTMUSIC_RGB_RHYTHM_LED_SHOW=0`）→ 所有音频完全干净，零噗噗声。

**根因**：WS2812 灯带驱动本身就与音频互相干扰，无论 bitbang 还是 DMA。可能的干扰路径：
- 176 颗 RGB LED 全亮时瞬时电流大（>10A），造成电源纹波耦合到音频
- DMA 控制器竞争（SPI DMA 和 I2S DMA 共用 DMA 引擎）
- 灯带数据线（GPIO14）与 I2S 信号线（GPIO6/39/38）之间的 PCB 串扰

**教训**：
- `audio_policy_set_user_dynamic_waterlevel_ms` 在此平台上副作用明显，不建议使用
- DSP 能量采集（`f_band_energy_en=1`）会破坏 A2DP 音频通路（原开发者已注释 "test if energy sampling steals audio output"）
- 灯带和音频无法在同一 SoC 上完美共存

### 3.3 DSP 能量采集破坏音频

**现象**：调用 `btmusic_output_energy_sample_config()` → `f_band_energy_en=1` 后，A2DP 无声音。

**排查过程**：lcmusic 和 audio_input 使用同样的 API 没问题，但 btmusic A2DP 通路不行。

**根因**：DSP 固件（`adMUSIC.dsp`）的 A2DP 解码链路与频带能量采集冲突。能量采集插入 DSP 效果链后，SBC/AAC 解码输出被截断。这是 DSP 固件级的问题，应用层无法绕过。

**教训**：DSP 能量采集在本地播放（文件解码）可用，但在蓝牙 A2DP 通路不可用。假律动（MCU 自行生成随机频谱）是不依赖 DSP 的可行替代方案。

### 3.4 AMBIC1010 时序临界

**现象**：WS2812/AMBIC1010 只亮第一颗灯珠，偶尔整排亮但颜色不对。

**排查过程**：
1. 用 WS2812 标准时序（T0H=350ns, T1L=350ns）→ 只亮第一颗
2. 放宽到 500ns/1200ns → 无改善
3. 查到 AMBIC1010 datasheet → 实际要求 T0H/T1L=300ns±50, T0L/T1H=900ns±50
4. 原时序 350ns 在容差边界外（300+50=350），属于临界值

**根因**：原代码用 WS2812 标准时序（350ns），超出 AMBIC1010 容差上限。init 时数据简单侥幸通过，频谱数据复杂时时序抖动导致后续灯珠丢数据。

**教训**：不同厂家的 WS2812 兼容芯片时序容差不同，务必查对应 datasheet。AMBIC1010 正确时序：**T0H/T1L=300ns, T0L/T1H=900ns**。

### 3.5 SPI+DMA 方案失败

**现象**：SPI+DMA（GPIO2, MFP=6 → SPI1_MOSI）驱动灯带，灯不亮或只亮半排。

**排查过程**：
1. 4-bit 编码（每 WS2812 bit = 4 SPI bit）→ 灯不亮
2. 手写 CMU_SPICLK 寄存器 → SPI 跑全速 78MHz → 时序完全不对
3. 改用 `soc_freq_set_spi_clk(1, 3333)` → SPI 最低只能到 ~6.6MHz（corepll 792MHz / 120）
4. 8-bit 编码（每 WS2812 bit = 8 SPI bit）→ 仍只亮半排

**根因**：SPI 时钟分频器范围有限（divider 1-30），corepll 792MHz 时 SPI1 最低只能到 26.4MHz。WS2812 需要每 bit 1.2µs（833kHz），SPI 达不到这么低的频率。即使 8-bit 编码也因实际 SPI 频率不可控而失败。

**教训**：在评估 SPI+DMA 方案前，务必确认 SPI 时钟分频器能否达到目标频率。ATS2853P2 的 SPI 分频器不适合驱动 WS2812 这种低速协议。

### 3.6 最终方案：外部 MCU

经过两周调试，确定**同一 SoC 上同时做高质量音频和 WS2812 灯带不可行**。最终方案：

- **ATS2853P2**：专注蓝牙音频 + 系统控制
- **外部 MCU（PY32F005）**：独立驱动 AMBIC1010 灯带（假律动，不依赖 DSP 能量）
- 通信：一个 GPIO 通知播放/停止状态（方案 A），或 UART 发送频带能量（方案 B）
- 驱动文档：见 `AMBIC1010_驱动说明.md`

## 4. 配置检查清单

播放音频前，确认以下配置：

```
[ ] CONFIG_CODEC_ACM8635=y
[ ] CONFIG_CODEC_ACM8635_I2C_BITBANG=y（或 hw I2C_0）
[ ] CONFIG_CODEC_ACM8635_INIT_VOLUME=8（非 0）
[ ] CONFIG_AUDIO_OUT_I2STX0_SUPPORT=y
[ ] GPIO6/39/38 MFP=0x9（I2STX0）
[ ] GPIO5 初始化为输出高（PDN 释放）
[ ] I2C bus recovery 后 chip ID 可读
[ ] acm8635_reg_tab_main 加载后有 10ms 延迟
[ ] BTMUSIC_RGB_RHYTHM_LED_SHOW=0（灯带关闭，避免干扰）
[ ] DSP 能量采集关闭（btmusic_output_energy_sample_config 被 #if 0）
[ ] audio_policy_set_user_dynamic_waterlevel_ms 为 0（不使用）
[ ] ACM8635 寄存器 0x04=0x03, 0x16=0x03（Play 状态确认）
```

## 5. 常见问题排查

| 现象 | 可能原因 | 检查方法 |
|------|---------|---------|
| 完全无声 | PDN 未拉高 | 测量 GPIO5 电压（应为高） |
| 完全无声 | I2C 通信失败 | 读 chip ID（0x00 寄存器） |
| 完全无声 | I2S 无输出 | 示波器测 GPIO38 是否有数据 |
| 完全无声 | 律动灯干扰 | 关闭 `BTMUSIC_RGB_RHYTHM_LED_SHOW` |
| 噗噗声 | 律动灯 bitbang irq_lock | 同上，关闭灯带看是否消失 |
| 噗噗声 | waterlevel 副作用 | 确认 waterlevel 为 0 |
| 只有右声道 | DSP 配置/ClassD 寄存器 | 检查 acm8635_reg_tab_main 的 EQ 段 |
| 音量太小 | init_volume 太低 | 查看 `CONFIG_CODEC_ACM8635_INIT_VOLUME` |
| 能量数据读不到 | DSP 能量采集未启用 | 确认 `btmusic_output_energy_sample_config` 被调用 |
| 能量数据读到但音频异常 | A2DP 通路冲突 | 关闭能量采集，用假律动替代 |
