## 1. 协议概述

本协议定义了 PY32F032E1xM7E1xM7 主控芯片与 ATS2853P2 蓝牙芯片之间的 UART 串行通信规范，采用 CRC16 校验确保数据传输可靠性。

**适用场景**：音响低压板中主控与蓝牙芯片的参数配置、状态交互、音频律动数据（10段频谱+播放状态，50ms周期）传输

## 3. 帧格式

### 3.1 帧结构

```
+------+------+------+--------+--------+
| Addr | CMD  | LEN  | DATA   | CRC16  |
| 1B   | 1B   | 1B   | N Bytes| 2Bytes |
+------+------+------+--------+--------+
```

### 3.2 字段说明

| 字段 | 长度 | 描述 |
|------|------|------|
| **Addr** | 1 字节 | 设备地址，主机发 0x01，从机发 0x02 |
| **CMD** | 1 字节 | 指令码，定义操作类型，支持批量操作 |
| **LEN** | 1 字节 | DATA 字段总长度 (0-255) |
| **DATA** | N 字节 | 指令参数，可包含多个子参数，按顺序排列 |
| **CRC16** | 2 字节 | CRC16 校验值，覆盖 Addr+CMD+LEN+DATA，**小端序** |

### 3.3 批量操作说明

- **发送帧**：支持在一帧中一次性设置多个参数（音量、高音、低音、震感强度、震感模式）
- **响应帧**：支持在一帧中一次性返回多个状态参数
- **数据顺序**：DATA 字段按固定顺序排列，无需单独指令码

### 3.4 帧结束判断

**超时机制**：通过接收超时判断一帧数据结束
- **超时时间**：40 bit 传送时间
- **计算公式**：40 / 115200 ≈ 0.347ms
- **实现方式**：接收字节间隔超过 0.35ms 即认为帧结束

### 3.5 CRC16 算法

**多项式**：`0x8005` (x¹⁶ + x¹⁵ + x² + 1)
**初始值**：`0xFFFF`
**计算范围**：Addr + CMD + LEN + DATA
**输出**：16 位 CRC 值（小端序传输）

**算法实现**：
```c
uint16_t crc16(uint8_t *data, uint16_t length) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++)
    {
        crc ^= data[i];
        
        for (uint8_t j = 0; j < 8; j++)
        {
            if (crc & 0x0001)
            {
                crc = (crc >> 1) ^ 0xA001;
            }
            else
            {
                crc >>= 1;
            }
        }
    }
    return crc;
}
```

## 4. 指令集

### 4.1 主机 → 从机（PY32F032E1xM7 → ATS2853P2）

| 设备地址 | 指令名称 | DATA 长度 | DATA 格式 | 功能描述 |
|--------|----------|-----------|-----------|----------|
| `0x01` | 批量设置参数（0x10） | 4 字节 | `[音量][高音][低音][震感强度]` | 一次性设置所有参数 |

**批量设置参数 DATA 格式（4 字节）：**
| 字节位置 | 参数 | 范围 | 说明 |
|----------|------|------|------|
| 0 | 音量 | 0-100 | 音量值 |
| 1 | 高音 | 0-24 | -12dB~+12dB（偏移 +12） |
| 2 | 低音 | 0-24 | -12dB~+12dB（偏移 +12） |
| 3 | 震感强度 | 0-24 | 震感强度值 |
| 4 | 开关机状态 | 0-1 | 开关机状态值 |

### 4.2 从机 → 主机（ATS2853P2 → PY32F032E1xM7）

| 设备地址 | 指令名称 | DATA 长度 | DATA 格式 | 功能描述 |
|--------|----------|-----------|-----------|----------|
| `0x02` | 批量设置参数（0x10） | 17 字节 | `[状态6B][频谱10B][播放1B]` | 一帧返回所有状态+律动数据，50ms 周期 |

**状态+律动响应 DATA 格式（17 字节）：**
| 字节位置 | 参数 | 范围 | 说明 |
|----------|------|------|------|
| 0 | 音量 | 0-100 | 当前音量 |
| 1 | 高音 | 0-24 | -12dB~+12dB（偏移 +12） |
| 2 | 低音 | 0-24 | -12dB~+12dB（偏移 +12） |
| 3 | 震感强度 | 0-100 | 当前震感强度 |
| 4 | 连接状态 | 0-1 | 0=断开, 1=已连接 |
| 5 | 错误码 | 0-255 | 0=正常, 非0=错误码（见下表） |
| 6~15 | band0~band9 | 0-255 | 10 段频谱能量值（低频→高频，0=静音） |
| 16 | 播放状态 | 0-1 | 0=暂停/停止，1=手机媒体播放中（AVRCP） |

> **律动说明**：
> - ATS2853P2 每 **50ms** 主动发送一帧，PY32 无需请求。
> - 停止播放时 band0~band9 全为 0，PY32 收到后切回氛围灯模式。
> - 播放中 band0~band9 为 DSP 实时频谱能量，PY32 据此驱动灯带律动。

### 4.3 错误码定义

| 错误码 | 描述 |
|--------|------|
| `0x01` | 指令不支持 |
| `0x02` | 参数长度错误 |
| `0x03` | 参数值无效 |
| `0x04` | CRC 校验错误 |
| `0x05` | 设备忙 |

## 5. 通信流程

### 5.1 主机发送指令流程

```
1. 构建完整帧数据（Addr + CMD + LEN + DATA + CRC16）
2. 一次性发送整帧数据，不逐字节发送
3. 等待响应（超时时间：100ms）
4. 一次性接收整帧响应数据
5. 校验 CRC16
6. 解析响应数据
```

### 5.2 从机响应流程

```
1. 一次性接收整帧数据
2. 提取 Addr、CMD、LEN、DATA、CRC16
3. 验证 CRC16
4. 执行指令
5. 构建完整响应帧（含 CRC16）
6. 一次性发送整帧响应数据
```

## 7. 通信示例

### 7.1 批量设置参数

**发送帧（设置：音量80%，高音0dB，低音0dB，震感50%）：**
```
0x01 0x10 0x04 0x50 0x0C 0x0C 0x32 0xD3 0x87
|Addr|CMD|LEN|音量|高音|低音|震感|CRC_L|CRC_H|
```
- Addr: 0x01 （设备地址）
- CMD: 0x10 (批量设置参数，0x10)
- LEN: 0x04 (4字节数据)
- DATA: [0x50, 0x0C, 0x0C, 0x32]
  - 音量: 80%
  - 高音: 0dB (0x0C - 12 = 0)
  - 低音: 0dB
  - 震感强度: 50%
- CRC16: CRCL CRC_H (小端序)

**CRC计算过程：**
```
数据: [0x01, 0x10, 0x04, 0x50, 0x0C, 0x0C, 0x32]
CRC = crc16([0x01, 0x10, 0x04, 0x50, 0x0C, 0x0C, 0x32], 6)
```

### 7.2 状态+律动响应（50ms 周期，一帧全包）

**响应帧（播放中，bands=[40,80,120,90,60,30,20,10,5,2]）：**
```
0x02 0x10 0x11 0x50 0x0C 0x0C 0x32 0x01 0x00  0x28 0x50 0x78 0x5A 0x3C 0x1E 0x14 0x0A 0x05 0x02  0x01  CRC_L CRC_H
|Addr|CMD|LEN |音量|高音|低音|震感|连接|错误|  b0   b1   b2   b3   b4   b5   b6   b7   b8   b9  |play| CRC16 |
```
- Addr: 0x02 （设备地址）
- CMD: 0x10 (状态+律动响应，0x10)   
- LEN: 0x11 (17字节数据)
- DATA[0~5]: 状态参数（音量80%, 高音0dB, 低音0dB, 震感50%, 已连接, 正常）
- DATA[6~15]: 10 段频谱能量（40, 80, 120, 90, 60, 30, 20, 10, 5, 2）
- DATA[16]: 播放状态=1 (正在播放)
- CRC16: CRCL CRC_H (小端序)

**响应帧（停止播放，频谱全零）：**
```
0x02 0x10 0x11 0x50 0x0C 0x0C 0x32 0x01 0x00  0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00 0x00  0x00  CRC_L CRC_H
```
- Addr: 0x02 （设备地址）
- CMD: 0x10 (状态+律动响应，0x10)   
- LEN: 0x11 (17字节数据)
- DATA[16]: 播放状态=0 (停止播放)
- PY32 收到后停止律动，切回氛围灯模式

## 8. 定时发送机制

| 场景 | 发送周期 | 方向 | 说明 |
|------|----------|------|------|
| 状态+律动数据 | **每 50ms** | ATS2853P2 → PY32F032E1xM7 | 音量/音效参数 + 10段频谱 + 播放状态，一帧全包 |
| 参数变更 | 立即发送 | PY32F032E1xM7 → ATS2853P2 | 音量/音效变化时立即同步 |
| 无重传机制 | — | — | 依赖定时发送保证数据同步 |

---

## 9. 注意事项

1. **字节序**：多字节数据采用小端序（Little-Endian）
2. **帧间隔**：帧与帧之间最小间隔 5ms
3. **帧结束判断**：接收字节间隔超过 0.35ms（40 bit 传送时间）即认为帧结束
4. **缓冲区**：建议接收缓冲区至少 32 字节
5. **异常处理**：不进行重传，依赖定时发送机制保证数据同步
6. **热启动**：ATS2853P2 上电后需等待 100ms 再发送指令

## 10. CRC16 计算示例代码

```c
#include <stdint.h>

uint16_t crc16(uint8_t *data, uint16_t length) {
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < length; i++) {
        crc ^= data[i];
        for (uint8_t j = 0; j < 8; j++) {
            if (crc & 0x0001) {
                crc = (crc >> 1) ^ 0x8005;
            } else {
                crc >>= 1;
            }
        }
    }
    return crc;
}

// 发送帧封装
void BT_SendFrame(uint8_t addr, uint8_t cmd, uint8_t *data, uint8_t len) {
    uint8_t frame[32];
    uint16_t crc;
    
    frame[0] = addr;            // Addr
    frame[1] = cmd;             // CMD
    frame[2] = len;             // LEN
    for (uint8_t i = 0; i < len; i++) {
        frame[3 + i] = data[i]; // DATA
    }
    
    // 计算 CRC（覆盖 Addr + CMD + LEN + DATA = len + 3 字节）
    crc = crc16(&frame[0], len + 3);
    frame[3 + len] = crc & 0xFF;      // CRC_L
    frame[4 + len] = (crc >> 8) & 0xFF; // CRC_H
    
    // 通过 UART 发送 frame[0..4+len]
    UART_Send(frame, 5 + len);
}

// 接收帧解析（一次性接收整帧）
bool BT_ReceiveFrame(uint8_t *addr, uint8_t *cmd, uint8_t *data, uint8_t *len) {
    uint8_t buffer[32];
    uint16_t crc_calc, crc_recv;
    uint8_t frame_len;
    
    // 先接收 Addr、CMD、LEN 和 CRC 前几个字节
    if (UART_Recv(buffer, 5, 1000) != 5) return false;
    
    *addr = buffer[0];
    *cmd = buffer[1];
    *len = buffer[2];
    frame_len = *len + 5;  // Addr(1) + CMD(1) + LEN(1) + DATA(N) + CRC(2)
    
    // 一次性接收剩余数据
    if (*len > 0 && UART_Recv(&buffer[5], *len, 1000) != *len) return false;
    
    // 提取 DATA
    for (uint8_t i = 0; i < *len; i++) {
        data[i] = buffer[3 + i];
    }
    
    // 提取 CRC16（小端序）
    crc_recv = buffer[3 + *len] | (buffer[4 + *len] << 8);
    
    // 验证 CRC（覆盖 Addr + CMD + LEN + DATA）
    crc_calc = crc16(buffer, *len + 3);
    
    return (crc_calc == crc_recv);
}
```
