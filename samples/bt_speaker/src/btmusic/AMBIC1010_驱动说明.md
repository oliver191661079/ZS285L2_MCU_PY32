# AMBIC1010 4×44 RGB LED 矩阵驱动说明

## 1. 硬件概述

- **芯片型号**：AMBIC1010（WS2812 兼容协议）
- **矩阵规格**：4 行 × 44 列 = 176 颗 RGB LED
- **像素格式**：GBR（Green-Blue-Red），MSB 先发
- **连接方式**：单线串联（DIN → DOUT 级联）
- **工作电压**：5V DC

### 1.1 引脚接线

```
外部 MCU GPIO ──── AMBIC1010 DIN（数据输入）
外部 5V 电源 ──── 灯带 VCC
电源 GND ──────── 灯带 GND + MCU GND（必须共地）
```

### 1.2 矩阵物理布局（蛇形走线）

数据从 **底部 Row0 LED0** 进入，蛇形串联到 **顶部 Row3 LED175**：

```
Row3 (最上)   LED132 ← LED133 ← ... ← LED175    col=43→0, 右往左
Row2          LED88  → LED89  → ... → LED131    col=0→43, 左往右
Row1          LED44  ← LED45  ← ... ← LED87     col=43→0, 右往左
Row0 (最下)   LED0   → LED1   → ... → LED43     col=0→43, 左往右
                ↑ 数据输入（接 MCU GPIO）
```

偶数行（Row0, Row2）从左到右，奇数行（Row1, Row3）从右到左。

## 2. 通信协议（时序）

### 2.1 码型时间

| 参数 | 符号 | 最小值 | 标称值 | 最大值 | 单位 |
|------|------|--------|--------|--------|------|
| 码周期 | T | — | 1.2 | — | µs |
| 0 码高电平 | T0H | 250 | 300 | 350 | ns |
| 0 码低电平 | T0L | 850 | 900 | 950 | ns |
| 1 码高电平 | T1H | 850 | 900 | 950 | ns |
| 1 码低电平 | T1L | 250 | 300 | 350 | ns |
| 复位时间 | Trst | 200 | — | — | µs |

### 2.2 波形示意

```
0 码:  ┌──┐          1 码:  ┌──────┐
       │  │                 │      │
       ┘  └─────────        ┘      └──
       ←300ns→←900ns→       ←900ns→←300ns→
```

### 2.3 数据帧格式

```
[LED0 G] [LED0 B] [LED0 R] [LED1 G] [LED1 B] [LED1 R] ... [LED175 R] [RESET>200µs]
│────────────────── 176 × 3 = 528 字节 ──────────────────│   │─ 拉低 ─│
```

- 每个 LED 占 3 字节：G（绿）、B（蓝）、R（红）
- 每字节 MSB 先发
- 全部 528 字节必须在一次 RESET 之前**连续发送**，中间低电平间隔不能超过 50µs
- 发送完毕后拉低数据线 ≥200µs，触发锁存

### 2.4 发送示例

设 LED0 显示纯红色（R=255, G=0, B=0）：

```
GBR = [0x00] [0x00] [0xFF]
发送: 00000000 00000000 11111111（MSB first）
```

LED0 收到后，将后续数据透传给 LED1，以此类推。

## 3. 软件驱动

### 3.1 文件清单

| 文件 | 说明 |
|------|------|
| `ambic1010_driver.h` | 头文件：API 声明、时序宏、矩阵参数 |
| `ambic1010_driver.c` | 驱动实现（纯 C，无依赖） |
| `ambic1010_hw_port.c` | 硬件抽象层示例（改 GPIO 即可用） |

### 3.2 移植步骤

**Step 1**：把 `.h` 和 `.c` 复制到 MCU 工程。

**Step 2**：实现 4 个硬件抽象函数（参考 `ambic1010_hw_port.c`）：

```c
// GPIO 输出高/低
void ambic1010_hw_gpio_set(int high);

// 微秒级忙等延迟
void ambic1010_hw_delay_us(unsigned int us);

// 关全局中断（返回状态）
unsigned int ambic1010_hw_irq_lock(void);

// 恢复中断
void ambic1010_hw_irq_unlock(unsigned int key);
```

**Step 3**：初始化：

```c
ambic1010_init();  // 上电复位 + 清空灯带
```

**Step 4**：定时刷新（建议 100~200ms 周期）：

```c
// 方式 A：假律动（随机跳）
ambic1010_show_rhythm_random();

// 方式 B：用 10 段频谱数据驱动
uint8_t band[10] = { 200, 150, 100, 80, 60, 40, 80, 120, 180, 255 };
ambic1010_show_spectrum(band);
```

### 3.3 API 参考

```c
void ambic1010_init(void);
// 初始化灯带。上电后调用一次。

// 生成随机频谱数据并刷新（一键假律动）。
```

## 4. 视觉效果说明

### 4.1 柱高逻辑

每列（4 颗竖排 LED）根据该列的能量值（0-255）决定亮几颗：

| 能量值 | 亮灯数 |
|--------|--------|
| 0 | 0（全灭） |
| 1-63 | 1 颗（最下） |
| 64-127 | 2 颗 |
| 128-191 | 3 颗 |
| 192-255 | 4 颗（满柱） |

### 4.2 颜色分组

44 列分为 15 组（每 3 列一组，最后一组 2 列），循环使用 15 色彩虹色板：

```
列 0-2   红色      列 9-11  青色      列 21-23 粉色
列 3-5   橙色      列 12-14 蓝色      列 24-26 橙色
列 6-8   黄色      列 15-17 靛色      ...
                  列 18-20 紫色
```

每 8 帧色板整体偏移一位，产生颜色流动效果。

### 4.3 亮度限制

为防止 176 颗全亮时过热，每列亮度钳制在 6~80（0-255 范围）。如需更亮或更暗，修改 `ambic1010_driver.h` 中的：

```c
#define AMBIC1010_BRIGHT_MAX  80   // 最大亮度（0-255）
#define AMBIC1010_BRIGHT_MIN  6    // 最小亮度
```

## 5. ATS2853P2 ↔ 外部 MCU 通信

### 5.1 方案 A：独立运行（推荐）

外部 MCU 自主运行假律动，ATS2853 只需一个 GPIO 通知播放状态：

```
ATS2853 GPIO ──→ MCU GPIO（高电平=播放中，低电平=停止）
```

MCU 检测到高电平时启动定时器刷新灯带，低电平时停止并清空灯带。

### 5.2 方案 B：UART 实时能量数据

ATS2853 读取 DSP 频带能量，通过 UART 发送给 MCU。协议：

```
帧格式：SYNC(1) + BAND0(1) + ... + BAND9(1) + CHK(1) = 12 字节

SYNC   = 0xA5（帧头标记）
BAND0..9 = 10 段频带能量（0-255，低频→高频）
CHK    = BAND0 ^ BAND1 ^ ... ^ BAND9（异或校验）

UART 参数：115200-8-N-1
发送周期：100-200ms
```

MCU 接收示例（UART RX ISR 中调用）：

```c
void uart_rx_byte(uint8_t byte)
{
    static uint8_t buf[12], pos;
    static uint8_t sync;

    if (!sync) {
        if (byte == 0xA5) { sync = 1; pos = 0; }
        return;
    }
    buf[pos++] = byte;
    if (pos >= 11) {          // 10 bands + 1 checksum
        uint8_t chk = 0;
        for (int i = 0; i < 10; i++) chk ^= buf[i];
        if (chk == buf[10]) { // 校验通过
            ambic1010_show_spectrum(buf);
        }
        sync = 0;
    }
}
```

> **注意**：方案 B 需要 ATS2853P2 启用 DSP 能量采集，但实测该功能在 A2DP 通路上会导致音频异常（噗噗声）。建议使用方案 A 的假律动模式。

## 6. 常见问题

### Q: 灯珠颜色不对或只亮几颗？

检查：
1. 时序是否在容差内（±50ns）
2. GPIO 驱动能力是否足够（建议推挽输出，驱动等级 ≥4）
3. RESET 脉冲是否 ≥200µs
4. 数据线是否接触良好
5. 5V 电源是否充足（全白时 176×60mA ≈ 10A，全亮需外接电源）

### Q: 中间不能拆分发送吗？

不能。WS2812 协议要求全部数据连续发送，中间空闲 >50µs 会触发锁存。一帧约 5ms（176×24×1.2µs），期间需关中断保护时序。

### Q: 如何适配不同 CPU 频率？

`ambic1010_hw_delay_us()` 中的延迟需要根据实际 CPU 频率校准。推荐用硬件定时器做微秒延迟，精度最高。NOP 循环方式需实测调整循环次数。

### Q: 如何调试时序？

用逻辑分析仪或示波器抓取数据线波形，验证：
- 0 码：约 300ns 高 + 900ns 低
- 1 码：约 900ns 高 + 300ns 低
- 帧尾：低电平 ≥200µs
